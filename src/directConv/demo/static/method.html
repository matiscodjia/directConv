Method

Where every number comes from.

Three kinds of numbers appear in the lab. They are never mixed in one figure.

Exact, measured, projected

exact
Bytes. Every tensor's shape is known when the program is built, so memory is a formula. The tests check it against Rust's size_of for every frame size.
measured
Times on this computer. Rust: the kernel alone (the copies between Python and Rust exist only because the lab is driven from Python). numpy: the whole of np.tensordot, its copy included, since the copy is part of how it works.
projected
Times on the STM32. The cycle counts measured on the real board (DWT counter, read over ST-Link) applied to the shapes at hand. Nothing runs on the board from this page yet.

The workload

A 3×3 Sobel-x filter and a 3×3 Gaussian filter over the luminance of each frame (0.299 R + 0.587 G + 0.114 B), stride 1, no padding, 32-bit floats. The output of an H×W frame is (H−2)×(W−2)×2. Luminance because the streaming strategy handles one channel: RGB would triple its memory.

Every strategy's output is compared with numpy's on the first and last frames of every run. They are bit-identical.

The chip

  • The stack is 126.4 kB (linker symbols). The compiler reserves the tensors plus 0.4 to 1.7 kB, measured from the stack margin at the entry of each run: ×1.006 to ×1.038.
  • Tensors up to about 121.5 kB are therefore predicted to fit. The largest convolution actually run on the chip is 72.2 kB.
  • The benchmark firmware still carries a 75 kB safety budget from before a stack bug was fixed; the 78 kB regime it once crashed on is now skipped, never run. Confirming the 128×72 wall means running that regime on the board.
  • The wall at 128×72 holds for any threshold between 107 and 126 kB, because 160×90 needs 169 kB, more than the whole stack.
  • This computer: the chip's rule (tensor bytes must fit) applied to an 8 MiB thread stack. The chip's overhead is assumed to hold there; it was not measured.

Statistics

  • The clip is processed batch by batch (about 24 batches per strategy). Each batch gives one time per frame; the lab shows the median and the 5th to 95th percentile of those, not one average.
  • A warm-up batch is run and thrown away first.
  • Long videos loop forward, then backward, so there is no jump cut and no frame is decoded twice. Memory does not grow with the length.
  • numpy's memory is measured in a fresh process (a peak never goes down), as the rise above the loaded batch, minus the output array.
  • Dropped frames follow a simple rule: a frame that arrives while the device is busy is lost, and the device takes the first one that arrives after it finishes.

Limits

  • Frame sizes are compiled ahead: a fixed ladder of 16:9 sizes. Streaming accepts any height, but only the widths on the ladder.
  • The Rust core runs on one thread, with no BLAS. f32 only.
  • Camera rates are capped by what H.264 can carry at each size (120 fps in Full HD).
